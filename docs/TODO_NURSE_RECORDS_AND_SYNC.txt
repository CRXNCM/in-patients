Nurse Records & Real-Time Synchronization — Engineering TODO
Generated from codebase audit. Do not treat items as implemented until checked off.

CONFIRMED ROOT CAUSES
1. Current Record stays filled because after save, a useEffect reloads the new pending record back into cart.
2. Live API ignores existingRecordId; POST always creates. Mock mode updates in place.
3. No real-time layer: no Socket.IO, SSE, React Query, or record polling. Each tab loads once.

RISK AREAS
================================================================================
Duplicate records     — API POST always creates; existingRecordId ignored.
Incorrect billing     — Duplicate pendings both approved; or nurse JWT source:reception auto-approves.
                      Pending itself is NOT billed today.
Stale balances        — Other session never calls refreshRecords; dashboards fetch once.
Unauthorized editing  — No PATCH yet; once added must lock approved/rejected/auto.
                      Nurse can already hit approve API via patients.edit.
Lost nurse data       — Cart is only cleared after successful await — keep that.
Duplicate notifications — addNotification Date.now() ids vs syncNotifications notif-${record.id}.
Race                  — Reception approves while nurse PATCHes; two nurses PATCH same pending.
Inconsistent multi-user — Context is per tab; sidebar badge and dashboard counts can disagree.
